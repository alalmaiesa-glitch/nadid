# Usage Quota Accounting & Billing Integrity V1

## الهدف

نَضِيد يبيع استخدامًا شهريًا بعدد الأحرف:
- مجاني: 50,000 حرف شهريًا.
- أساسي: 500,000 حرف شهريًا.
- احترافي: 2,000,000 حرف شهريًا.
- أرصدة Top-up اختيارية عند نفاد الرصيد.

هذه الطبقة تجعل تلك الأرقام سياسة تشغيلية فعلية وليست مجرد بيانات باقات.

## العقد

1. لا يخصم أي شيء قبل نجاح التحليل.
2. بعد نجاح التحليل يحسب عدد الأحرف المستخرجة فعليًا.
3. يستهلك الرصيد الشهري أولًا ثم Top-up.
4. إذا لم يكفِ المجموع، ترفض العملية كاملة بلا خصم جزئي.
5. كل عملية ناجحة تسجل في Ledger دائم.
6. إعادة نفس operation لا تخصم مرتين.
7. الاستهلاك لكل مستخدم متسلسل ذريًا داخل PostgreSQL لمنع سباقات الطلبات المتزامنة.
8. العميل المصادق لا يستطيع استدعاء RPC الخصم مباشرة؛ التنفيذ محصور في service_role.
9. في Production يفشل الحارس مغلقًا عند غياب الهوية أو خدمة الحصص أو فشل RPC.

## البنية

- `character_usage_monthly`: الرصيد الشهري المستهلك.
- `credit_topups`: الأرصدة الإضافية.
- `character_usage_events`: Ledger دائم لكل عملية خصم.
- `consume_character_quota(...)`: RPC ذرية مسؤولة عن القرار والخصم.

## ترتيب الخصم

- Included monthly characters.
- ثم Top-up المتاح بترتيب التفعيل/الإنشاء.

لا تنشأ Usage Event للعملية المرفوضة.

## نقطة التطبيق

`/api/analyze` ينفذ:
1. Auth.
2. Rate limit.
3. Bounds.
4. تحليل DOCX.
5. حساب الأحرف من Blocks المستخرجة.
6. Quota consumption.
7. Persistence.
8. Response.

وبذلك لا يحاسب المستخدم على تحليل فاشل، ولا يتسلم تحليلًا ناجحًا خارج حصته.

## الاختبارات

- `QUOTA-001..QUOTA-010`: حراس معمارية وربط API.
- PostgreSQL fault-injection: الخطة المجانية، الخطة الاحترافية، idempotency، أولوية included، استخدام Top-up، رفض الرصيد غير الكافي بلا mutation، وصلاحيات RPC.
