# Malformed Document & Failure Recovery V1

## الهدف

هذه الطبقة تختبر كيف يتصرف نَضِيد عندما يكون ملف DOCX:

- غير صالح أصلًا.
- ZIP ناقصًا أو مقطوعًا.
- حزمة OOXML ناقصة.
- XML الداخلي فيها تالفًا.
- تحتوي مسارات ZIP خطرة.
- تحتوي أسماء Entries مكررة تسبب غموضًا في قراءة الحزمة.
- لا تحتوي محتوى قابلًا للمراجعة.
- غير اعتيادية لكنها صحيحة وكبيرة نسبيًا.

الهدف ليس فقط منع crash. عقد V1 هو:

1. الملف غير الصالح يُرفض بحالة HTTP محددة ومفهومة.
2. لا يتسرب Exception غير معالج إلى 5xx بسبب ملف المستخدم.
3. Endpoints التحليل العادي والعميق والتطبيق تتصرف بصورة متسقة عند فساد Parser.
4. الملفات الصعبة لكنها صحيحة لا تُرفض لمجرد أنها غير اعتيادية.
5. لا يُعاد مستند جزئي أو مضلل بعد فشل المعالجة.

## إصلاح اكتشفته V1

قبل هذه الطبقة كان:

- `/v1/analyze/docx` يحول فشل Parser إلى 422.
- `/v1/analyze/docx/deep` و`/v1/apply/docx` يستدعيان Parser مباشرة.

هذا يعني أن DOCX له ZIP مقبول مبدئيًا لكن XML داخلي تالف يمكن أن يؤدي إلى Exception غير منضبط في المسارين الأخيرين.

تم توحيد Parsing عبر helper يفشل مغلقًا إلى:

- HTTP 422
- `Could not parse the DOCX file.`

كما أضيف رفض صريح لـ duplicate ZIP entries لأن الحزمة ذات الاسم المكرر غامضة وقد تقرأها الأدوات المختلفة بصورة مختلفة.

## Benchmark

V1 تحتوي 24 حالة `MAL-001` إلى `MAL-024`، وتشمل:

- امتدادًا غير مدعوم.
- ملفًا فارغًا.
- bytes ليست ZIP.
- ZIP مقطوعًا.
- غياب Content Types.
- غياب document.xml.
- Zip Slip بصيغتي slash وbackslash ومسار absolute.
- duplicate document.xml.
- document.xml تالفًا عبر endpoints الثلاثة.
- package relationships مفقودة.
- مستندًا فارغًا أو whitespace only.
- فقرة واحدة ضخمة لكنها صحيحة.
- جدولًا كثيفًا من 900 خلية.
- امتداد DOCX بحروف كبيرة.
- عدد ZIP entries أعلى من الحد.
- Content Types XML تالفًا.
- apply بدون تعديلات على ملف صالح.
- حزمة ZIP مزيفة تحمل الاسمين المطلوبين فقط.
- حد 500,000 كلمة.

## Success contract

كل حالة لها Expected Outcome صريح. يفشل Benchmark إذا:

- اختلف Status المتوقع.
- غاب سبب الرفض المطلوب في الحالات الحساسة.
- ظهر أي HTTP 5xx.
- فشل مستند valid-but-unusual كان يجب قبوله.
- انخفض عدد العقد في Fixture الجدول الكثيف عن الحد المتوقع.

## حدود V1

هذه الطبقة لا تدعي أنها Fuzzer عام لـ OOXML. ولا تختبر كل أشكال:

- OLE.
- SmartArt.
- ActiveX.
- Track Changes المعقد.
- ملفات Word المشفرة على مستوى OOXML.
- ZIP bombs ذات أحجام فعلية ضخمة في CI.

هذه تحتاج طبقات أمنية/Fuzzing منفصلة. V1 تركز على Failure Recovery وسلوك API الحتمي.
