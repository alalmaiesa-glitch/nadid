# Human Gold Set v1

## لماذا هذه الطبقة؟

الـBenchmark المصطنع يثبت أن القواعد تعمل في الحالات التي صممناها. Corpus الواقعي يثبت أن النظام لا ينهار على مستندات حقيقية. لكن Precision وRecall لا يصبحان حقيقيين إلا بعد مراجعة بشرية مستقلة.

لذلك يفصل نَضِيد بوضوح بين:
- Gold Candidate: عينة مستخرجة آليًا بانتظار المراجع.
- Human Gold: عينة اكتمل تحكيمها بشريًا.
- Metrics: لا تُسمى نهائية ما دام أي عنصر أو اقتراح Pending.

## وحدة التحكيم

المراجع يراجع العقدة النصية كاملة، لا الاقتراح منفردًا فقط. النتائج المطلوبة:
- correct: اقتراح نَضِيد صحيح.
- wrong: اقتراح نَضِيد غير صحيح أو ليس التصحيح المناسب.
- missed: خطأ حقيقي في العقدة لم يقترح نَضِيد تصحيحه.

بهذا يمكن حساب Precision وRecall وF1 دون خلط بين كثرة الاقتراحات وجودتها.

## تصميم العينة V1

- 120 عقدة تحتوي اقتراحات.
- 120 عقدة بلا اقتراحات.
- توزيع دوري على المستندات وأنواع العقد لتقليل هيمنة ملف واحد.
- Seed ثابت لإعادة إنتاج العينة.
- وزن Sampling لكل عقدة لتعويض اختلاف نسب السحب بين الطبقات.

## بروتوكول بشري صارم

1. لا يرى المراجع أي حكم مسبق على الاقتراح.
2. يقرأ العقدة كاملة قبل وضع التصنيف.
3. كل اقتراح يأخذ correct أو wrong.
4. يسجل كل خطأ إضافي غير مكتشف في missed.
5. لا تُحسب الاختلافات الذوقية البحتة كـ Missed.
6. لا تُحسب إعادة الصياغة الأفضل شخصيًا ما لم يكن هناك خلل واضح ضمن نطاق نَضِيد.
7. أي تعديل قد يغيّر حقيقة أو التزامًا أو شرطًا يخضع لـ Meaning Lock.
8. النسخة Gold لا تعتمد إلا بعد اكتمال كل الوحدات.
9. يراجع مراجع ثانٍ عينة عشوائية لا تقل عن 20%، وكل حالات wrong وmissed عالية الأثر.
10. الخلافات تُحسم بالتحكيم قبل اعتماد القياس.

## الخصوصية

ملف Human Gold الخاص قد يحتوي نصوصًا من المستندات، لذلك يبقى داخل benchmark/gold/private/ ولا يُرفع إلى Git.

المستودع العام يحتوي فقط على أدوات السحب والقياس، مثال صناعي، تقارير تجميعية بلا نصوص خاصة، وحالات Regression منزوعة الهوية.

## قاعدة الإصدار

لا يجوز كتابة Precision أو Recall كنسبة جودة حقيقية لنَضِيد اعتمادًا على الاختبارات المصطنعة أو pre-label آلي. لا تعتمد النسب النهائية إلا من Human Gold مكتمل التحكيم.


## المسار المرحلي بعد اعتماد Silver Set

اعتمد المشروع Silver Set كطبقة تشخيص آلية مستمرة لتقليل عبء المراجعة اليدوية. لا يحل Silver Set محل Human Gold ولا يغيّر قاعدة الإصدار أعلاه.

المسار المعتمد:
1. تشغيل Silver Set على corpus الكامل.
2. تحويل الحالات عالية الأولوية من Wrong / Missed إلى Regression Cases.
3. تجميع Uncertain والحالات عالية الأثر فقط للمراجعة البشرية الصغيرة لاحقًا.
4. لا تُسمى أي نسبة ناتجة من Silver Set «دقة بشرية» أو «Human Precision/Recall».
