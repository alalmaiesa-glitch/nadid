# Document Memory v0.2

## الهدف

تحويل ذاكرة نَضِيد من قائمة كلمات متكررة وحقائق رقمية إلى ذاكرة معرفية للمستند يمكن الرجوع إليها أثناء المراجعة العميقة.

## العناصر التي تحفظها الذاكرة

- العناوين وبنية المستند.
- المصطلحات المتكررة.
- المفاهيم متعددة الكلمات التي تتكرر عبر مواضع مختلفة.
- الجهات والكيانات المهمة.
- التعريفات الصريحة للمصطلحات.
- الاختصارات وربطها بالاسم الكامل.
- القرارات المعتمدة.
- العلاقات الصريحة بين الجهات والأدوار والموضوعات.
- الالتزامات والواجبات.
- الشروط.
- المراجع النظامية والمعايير.
- الحقائق الرقمية والتعارضات المكتشفة.
- مواقع ظهور كل عنصر داخل المستند.

## مبادئ صارمة

- كل عنصر ذاكرة يحتفظ بـ node_ids التي تثبت مواضع ظهوره.
- العناصر المستخرجة لا تتحول إلى "حقيقة مؤكدة" خارج حدود النص.
- لا تُنشأ مفاهيم متكررة من ظهور واحد فقط.
- التعريفات لا تُستنتج من العناوين التي تحتوي على نقطتين.
- أي استخراج ضعيف الثقة يجب أن يبقى قابلًا للتدقيق ولا يستخدم لتغيير النص تلقائيًا.
- الذاكرة تخدم المراجعة ولا تستبدل النص الأصلي بوصفها مصدر الحقيقة.

## البنية

Document → Nodes → Protected Spans → Facts + Knowledge Memory → Context Retrieval → Review

تُحفظ العناصر في جدول `document_memory_items` مع النوع، المفتاح، القيمة، مواضع الظهور، الأسماء البديلة، الثقة، والبيانات المساندة.

## القياس

البعد الخاص بالذاكرة داخل Nadid Quality Benchmark هو `document_memory`، والهدف الأولي المعتمد 95% قبل تحويله إلى Quality Gate إلزامي.
