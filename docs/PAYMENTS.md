# مدفوعات نَضِيد

## المزوّد

Moyasar هو المزوّد الأساسي المقترح لنَضِيد.

## الاستخدامات

نفصل كل عملية مالية حسب الغرض:

- `support` — مساهمة اختيارية في تطوير نَضِيد.
- `service` — شراء خدمة أو رصيد أو معالجة مدفوعة.
- `subscription` — اشتراك دوري في خطة نَضِيد.

## التدفق

```
المستخدم
  ↓
اختيار المبلغ أو الخطة
  ↓
Moyasar Payment Form
  ↓
3-D Secure / وسيلة الدفع
  ↓
callback
  ↓
تحقق Server-side من:
  status + amount + currency
  ↓
payments table
  ↓
Webhook للمزامنة النهائية
```

## المتغيرات

```env
NEXT_PUBLIC_MOYASAR_PUBLISHABLE_KEY=
MOYASAR_SECRET_KEY=
MOYASAR_WEBHOOK_SECRET=
```

المفتاح السري لا يرسل إلى المتصفح مطلقًا.

## باقات الإطلاق

- مجاني: 0 ر.س شهريًا، 50,000 حرف شهريًا، مع إعلانات Google بعد اعتماد النطاق في AdSense.
- أساسي: 29 ر.س شهريًا أو 290 ر.س سنويًا، 500,000 حرف شهريًا.
- احترافي: 59 ر.س شهريًا أو 590 ر.س سنويًا، 2,000,000 حرف شهريًا.

يُحتسب الاستهلاك بالأحرف مع المسافات، ويتجدد الحد شهريًا حتى في الاشتراك السنوي.

تم نقل أساس الفوترة من الوضع المؤجل إلى migration `0017_billing_foundation.sql` ويتضمن:

- `payments`
- `billing_plans`
- `subscriptions`

المزايا وحدود كل باقة تُقرأ من `entitlements`، ولا يمنح العميل نفسه اشتراكًا أو يغيّر حالة الدفع مباشرة بسبب RLS.

## قاعدة أمان

لا نعتمد على نتيجة redirect وحدها. بعد عودة المستخدم من Moyasar يجب جلب العملية من API والتحقق من:

1. أن الحالة `paid`.
2. أن المبلغ يطابق طلب نَضِيد.
3. أن العملة تطابق الطلب.

ثم فقط نحدّث العملية إلى `paid` ونمنح الخدمة أو الرصيد.
